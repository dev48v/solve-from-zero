⭐ Favicon Generator — a real, from-scratch, entirely in-browser favicon maker: build an icon from either a typed letter or emoji (with your chosen background & text colour, a square / rounded / circle shape and a font) or an uploaded image (real FileReader.readAsDataURL, never uploaded to a server) — every design is rasterised fresh on a <canvas> at each of the standard sizes (16 · 32 · 48 · 180 apple-touch · 192 · 512) rather than shrinking one big image, so each pixel size gets a crisp render · live previews at real size plus a fake browser-tab and an iOS home-screen mock, one-click PNG downloads per size via canvas.toBlob + an object-URL <a download>, and it emits the exact HTML <link> tags + a ready site.webmanifest JSON referencing those filenames · modern favicons are PNGs, not multi-size .ico (that is now a niche) · distinct from the Day-10 QR generator · vanilla JS, no library

One little icon, half a dozen sizes, and a snippet to wire it up.

A favicon is that tiny square in the browser tab, the bookmark, the phone home screen. Making one used to mean a round-trip through an upload site. It never needed to: a browser can already draw and encode images. This tool builds a favicon two ways — type a letter or emoji and pick a background, shape and font, or drop your own image (read locally with FileReader, nothing leaves the page). Then it rasterises the design freshly at each standard size on a <canvas> — 16, 32 and 48 for the tab, 180 for Apple's touch icon, 192 and 512 for Android / PWA — because a crisp 16×16 wants its own render, not a shrunk 512. Each size downloads as a PNG through canvas.toBlob and an object-URL link, and the tool hands you the exact <link> tags and a site.webmanifest to paste into your <head>. All client-side, no library, no upload.

Five things worth knowing about favicons

        
1. PNG beat .ico. The old favicon.ico was a Windows container that could hold several sizes in one file. Every current browser accepts a plain PNG via <link rel="icon" type="image/png" sizes="…">, so multi-size .ico is now a niche compatibility trick, not the default — this tool ships PNGs, one per size. 2. Rasterise per size, do not shrink one big image. A 16×16 has 256 pixels to say everything with; a design auto-shrunk from 512 turns to mush. Drawing fresh at each size lets the shape and glyph stay legible where it counts. 3. Apple does its own thing. iOS ignores rel="icon" and wants rel="apple-touch-icon" at 180×180, and it rounds the corners itself — so give it a full-bleed square and let the OS mask it. 4. Android reads the manifest. The 192 and 512 icons are declared in site.webmanifest, and purpose:"maskable" tells Android it may crop into a circle/squircle — keep important art in the centre "safe zone". 5. It is just canvas + a Blob. No server, no library: draw on a <canvas>, call toBlob to encode a PNG, wrap it in an object URL, and click a hidden <a download>. The same three steps export any image a browser can draw.

🔨 Build it yourself

    
A favicon generator is a small pipeline: describe a design (a glyph with colours and a shape, or an uploaded image), write one renderAt(canvas, size) that draws it fresh at any pixel size, then loop the standard sizes calling canvas.toBlob to download a PNG each. The rest is presentation — live previews, a fake browser tab, the <link> tags and a manifest. No image library, no server; the browser already draws and encodes PNGs. Here it is, step by step.

    
    
      
  1. 
        
    1
    One design object, two sources
    
        
    Hold the whole icon as plain data: a mode (glyph or image), the glyph text, foreground/background colours, a font, a shape, and — for uploads — a decoded Image. Everything downstream reads only this object, so a control change is just a field write plus a redraw.
    
        
    const design = {
  mode: "glyph",          // "glyph" | "image"
  text: "D",
  fg:   "#ffffff",        // glyph colour
  bg:   "#f59e0b",        // background / backdrop
  font: "system-ui, sans-serif",
  shape:"rounded",        // "square" | "rounded" | "circle"
  img:  null,             // decoded HTMLImageElement (image mode)
  appName: "My App",
  theme:   "#0f172a"
};
    
      
    2. 
      
  2. 
        
    2
    The shape is a clip path
    
        
    Square, rounded and circle are all one idea: build a path, then clip() so everything drawn afterwards is masked to it. A circle is an arc; a rounded square is four arcTo corners scaled to the size so the radius looks right at 16 and at 512 alike.
    
        
    function clipShape(ctx, size, shape){
  ctx.beginPath();
  if (shape === "circle")      ctx.arc(size/2, size/2, size/2, 0, Math.PI*2);
  else if (shape === "rounded")roundRect(ctx, 0, 0, size, size, size*0.2);
  else                         ctx.rect(0, 0, size, size);
}
function roundRect(ctx, x, y, w, h, r){
  ctx.moveTo(x+r, y);
  ctx.arcTo(x+w, y,   x+w, y+h, r);
  ctx.arcTo(x+w, y+h, x,   y+h, r);
  ctx.arcTo(x,   y+h, x,   y,   r);
  ctx.arcTo(x,   y,   x+w, y,   r);
  ctx.closePath();
}
    
      
    3. 
      
  3. 
        
    3
    Centre a glyph — letter or emoji
    
        
    Set textAlign:"center" and textBaseline:"middle" so one fillText at the centre lands centred at any size. Scale the font to the icon size (emoji sit a little larger and ignore the fill colour — the OS paints their own).
    
        
    function drawGlyph(ctx, size){
  const t = design.text;
  if (!t) return;
  const isEmoji = /\p{Extended_Pictographic}/u.test(t);
  ctx.fillStyle    = design.fg;
  ctx.textAlign    = "center";
  ctx.textBaseline = "middle";
  ctx.font = `700 ${Math.round(size * (isEmoji ? 0.74 : 0.62))}px ${design.font}`;
  ctx.fillText(t, size/2, size/2 + size*0.02);   // tiny optical nudge
}
    
      
    4. 
      
  4. 
        
    4
    Read an upload locally, cover-fit it
    
        
    FileReader.readAsDataURL turns the picked file into a data URI — no upload — which an Image decodes. Then cover-fit it into the square: scale by the larger ratio so the icon is fully covered, and centre the overflow.
    
        
    function loadFile(file){
  const r = new FileReader();
  r.onload = () => { const im = new Image();
    im.onload = () => { design.img = im; redraw(); };
    im.src = r.result; };            // data: URI, nothing leaves the page
  r.readAsDataURL(file);
}
function drawCover(ctx, img, size){
  const s = Math.max(size / img.width, size / img.height);   // cover, not contain
  const w = img.width * s, h = img.height * s;
  ctx.drawImage(img, (size - w)/2, (size - h)/2, w, h);
}
    
      
    5. 
      
  5. 
        
    5
    renderAt(size) — the one function everything calls
    
        
    Size the canvas, clip to the shape, paint the backdrop, then either the glyph or the cover-fit image. Because it takes the size as an argument, the 16px tab preview and the 512px download run the same code — a fresh raster each time, never a downscale of one big bitmap.
    
        
    function renderAt(canvas, size){
  canvas.width = canvas.height = size;
  const ctx = canvas.getContext("2d");
  ctx.clearRect(0, 0, size, size);
  ctx.save();
  clipShape(ctx, size, design.shape); ctx.clip();   // mask to square/rounded/circle
  ctx.fillStyle = design.bg; ctx.fillRect(0, 0, size, size);
  if (design.mode === "image" && design.img) drawCover(ctx, design.img, size);
  else                                        drawGlyph(ctx, size);
  ctx.restore();
  return canvas;
}
    
      
    6. 
      
  6. 
        
    6
    The standard sizes and their filenames
    
        
    One table drives the downloads, the <link> tags and the manifest, so they can never drift apart. 16/32/48 are the classic favicon sizes, 180 is Apple's touch icon, 192 and 512 are the Android / PWA icons declared in the manifest.
    
        
    const OUTPUTS = [
  { size:16,  file:"favicon-16x16.png",         rel:"icon" },
  { size:32,  file:"favicon-32x32.png",         rel:"icon" },
  { size:48,  file:"favicon-48x48.png",         rel:"icon" },
  { size:180, file:"apple-touch-icon.png",      rel:"apple-touch-icon" },
  { size:192, file:"android-chrome-192x192.png",rel:"manifest" },
  { size:512, file:"android-chrome-512x512.png",rel:"manifest" },
];
    
      
    7. 
      
  7. 
        
    7
    Encode a PNG and download it — no server
    
        
    Render at the size onto a throwaway canvas, ask the browser to encode a PNG with toBlob, wrap the blob in an object URL and click a hidden <a download>. Revoke the URL afterwards so it is not leaked. That is the entire "export" — the browser is the image encoder.
    
        
    function downloadPNG(size, file){
  const c = document.createElement("canvas");
  renderAt(c, size);
  c.toBlob(blob => {
    const url = URL.createObjectURL(blob);
    const a = Object.assign(document.createElement("a"), { href:url, download:file });
    a.click();
    setTimeout(() => URL.revokeObjectURL(url), 1000);
  }, "image/png");
}
    
      
    8. 
      
  8. 
        
    8
    Emit the <link> tags
    
        
    Modern favicons are wired with PNG <link>s. rel="icon" with a sizes hint covers the tab; Apple needs its own rel="apple-touch-icon" at 180; a rel="manifest" points to the JSON; and a theme-color meta tints mobile UI. This is the copy-paste your <head> needs.
    
        
    function linkTags(){
  return [
    `<link rel="icon" type="image/png" sizes="16x16" href="/favicon-16x16.png">`,
    `<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32x32.png">`,
    `<link rel="icon" type="image/png" sizes="48x48" href="/favicon-48x48.png">`,
    `<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png">`,
    `<link rel="manifest" href="/site.webmanifest">`,
    `<meta name="theme-color" content="${design.theme}">`
  ].join("\n");
}
    
      
    9. 
      
  9. 
        
    9
    Build the site.webmanifest
    
        
    Android and installable PWAs read the icons from a manifest, not the <head>. Declare the 192 and 512 PNGs, mark 512 "any maskable" so the launcher may crop it to its own shape, and carry the name, theme and background colours through. JSON.stringify makes the file.
    
        
    function manifestJSON(){
  return JSON.stringify({
    name: design.appName, short_name: design.appName,
    icons: [
      { src:"/android-chrome-192x192.png", sizes:"192x192", type:"image/png" },
      { src:"/android-chrome-512x512.png", sizes:"512x512", type:"image/png",
        purpose:"any maskable" }
    ],
    theme_color: design.theme, background_color: design.bg,
    display: "standalone"
  }, null, 2);
}
    
      
    10. 
      
  10. 
        
    10
    Prove it with a self-test
    
        
    Trust the pipeline by checking it renders something at every size, and that the emitted tags and manifest reference the exact sizes and filenames in the table. Read the canvas back with getImageData and assert some pixels are opaque.
    
        
    const c = document.createElement("canvas");
OUTPUTS.forEach(o => {
  renderAt(c, o.size);
  console.assert(c.width === o.size, "canvas sized " + o.size);
  const px = c.getContext("2d").getImageData(0, 0, o.size, o.size).data;
  let opaque = 0; for (let i = 3; i < px.length; i += 4) if (px[i]) opaque++;
  console.assert(opaque > 0, "non-empty render at " + o.size);
});
console.assert(linkTags().includes('sizes="16x16"'), "16 link tag");
console.assert(JSON.parse(manifestJSON()).icons.length === 2, "manifest icons");
