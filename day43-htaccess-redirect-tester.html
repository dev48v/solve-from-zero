🔀 .htaccess Redirect Tester — paste Apache rewrite rules + a URL, see which rule wins, the captured groups, the target, and redirect-vs-rewrite — with real RegExp

Stop guessing what your .htaccess does. Watch it run.

An Apache .htaccess file rewrites and redirects URLs with rules like RewriteRule ^products/([0-9]+)$ product.php?id=$1 [L]. Each pattern is a real regular expression matched against the requested path, top to bottom, until one matches — and the flags decide whether the browser is quietly served different content (an internal rewrite) or bounced to a new address (a 301/302 redirect). Get the order or a [L] wrong and requests fall through to the wrong rule. This tester parses your rules, matches the URL with the browser's own RegExp engine — nothing faked, nothing uploaded — and shows you the winning rule, the captured $1… groups, the substituted target, and exactly what the browser would see.

Five things people get wrong about .htaccess rewrites

1. The pattern doesn't see the leading slash. In a per-directory .htaccess, Apache strips the leading / before matching, so ^/products almost never matches — write ^products. This tester matches against the slash-stripped path and warns you if a pattern starts with ^/. 2. Order + [L] decide everything. Rules run top to bottom; the first match wins, and [L] stops further processing. Put your specific rules above your catch-all, or the catch-all eats them. 3. Rewrite ≠ redirect. No [R] flag = an internal rewrite (the address bar never changes, the server just serves different content). Add [R=301] — or make the target an absolute http(s):// URL — and the browser is actually redirected. 4. RewriteCond only guards the very next RewriteRule. Conditions don't stack onto later rules; a blank line or another rule ends the group. 5. Redirect is prefix, RedirectMatch is regex. Redirect /old /new catches /old and everything under it; use RedirectMatch when you need a pattern with $1 backreferences.

🔨 Build it yourself

    
A redirect tester sounds like it needs an Apache server — it doesn't. Every RewriteRule pattern is an ordinary regular expression, and your browser already ships a world-class regex engine: RegExp. So the whole tool is parse the rules into structs, then replay them against a path in order. Split the file into lines, tokenize each rule's arguments (respecting quotes), read the [flags], attach any RewriteCond guards to the rule that follows, then match with new RegExp(pattern), splice the $1… captures into the substitution, and classify the outcome as an internal rewrite or a real redirect. [L] just means "stop the loop." No server, no upload — here's the whole engine, one honest step at a time.

    
    
      
  1. 
        
    1
    Read the file line by line
    
        
    An .htaccess is just text. Split on newlines, drop blank lines and # comments, and look at the first word of each line to route it: RewriteCond, RewriteRule, Redirect, RedirectMatch. Directives we don't simulate (RewriteEngine, RewriteBase, Options) are skipped so they don't pollute the trace.
    
        
    function parseRules(text){
  const rules = [];
  let pendingConds = [];
  for (const raw of text.split(/\r?\n/)){
    const line = raw.trim();
    if (!line || line[0] === "#") continue;
    if (/^(RewriteEngine|RewriteBase|Options|Header|Order|Allow|Deny)\b/i.test(line)) continue;

    let m;
    if ((m = line.match(/^RewriteCond\s+(.+)/i))) { pendingConds.push(parseCond(m[1])); continue; }
    if ((m = line.match(/^RewriteRule\s+(.+)/i))) { rules.push(parseRewriteRule(m[1], pendingConds)); pendingConds = []; continue; }
    if ((m = line.match(/^Redirect(Match)?\s+(.+)/i))) { rules.push(parseRedirect(!!m[1], m[2])); pendingConds = []; continue; }
  }
  return rules;
}

  2. 
        
    2
    Tokenize the arguments (quotes matter)
    
        
    A rule's arguments are space-separated, but a pattern or substitution can be wrapped in quotes to protect literal spaces. A tiny regex tokenizer pulls out double-quoted, single-quoted, or bare tokens — so "^my page$" stays one token.
    
        
    function tokenize(str){
  const out = [], re = /"([^"]*)"|'([^']*)'|(\S+)/g;
  let m;
  while ((m = re.exec(str)) !== null)
    out.push(m[1] ?? m[2] ?? m[3]);   // whichever group matched
  return out;
}
// 'RewriteRule ^products/([0-9]+)$ product.php?id=$1 [L,QSA]'
//   -> ['^products/([0-9]+)$', 'product.php?id=$1', '[L,QSA]']
    
      
    3. 
      
  3. 
        
    3
    Parse the [flags]
    
        
    The bracketed tail is a comma list. Strip the brackets, split on commas, and store each flag — some are bare (L, QSA, NC) and some carry a value (R=301). Keeping both a name→value map and a raw list makes them easy to test and to display.
    
        
    function parseFlags(str){
  const f = { list: [] };
  if (!str) return f;
  for (let tok of str.replace(/^\[|\]$/g, "").split(",")){
    tok = tok.trim(); if (!tok) continue;
    f.list.push(tok);
    const eq = tok.indexOf("=");
    const name = (eq === -1 ? tok : tok.slice(0, eq)).toUpperCase();
    f[name] = eq === -1 ? true : tok.slice(eq + 1);   // R -> true, R=301 -> "301"
  }
  return f;
}
    
      
    4. 
      
  4. 
        
    4
    Match with real RegExp
    
        
    This is the heart of it — and it's genuine. In a per-directory context Apache strips the leading slash, so match against path.replace(/^\//,""). The [NC] flag becomes the JS i flag. Wrap new RegExp in a try/catch so a bad pattern reports an error instead of throwing.
    
        
    function matchRule(pattern, flags, path){
  const subject = path.replace(/^\//, "");        // per-directory: no leading slash
  let regex;
  try { regex = new RegExp(pattern, flags.NC ? "i" : ""); }
  catch (e) { return { error: e.message }; }
  return { subject, regex, match: subject.match(regex) };  // match[0], match[1]=$1 ...
}

  5. 
        
    5
    Substitute the backreferences
    
        
    The substitution string carries $1…$9 (captures from the rule's pattern) and %1…%9 (captures from the last matched RewriteCond), plus %{VARS} like %{HTTP_HOST}. Three .replace calls with the match arrays turn the template into the real target.
    
        
    function applySub(sub, ruleMatch, condMatch, ctx){
  if (sub === "-") return null;                    // "-" means: change nothing
  return sub
    .replace(/\$(\d)/g, (_, d) => ruleMatch?.[+d] ?? "")   // $1 from the RewriteRule
    .replace(/%(\d)/g,  (_, d) => condMatch?.[+d] ?? "")   // %1 from the RewriteCond
    .replace(/%\{([^}]+)\}/g, (_, v) => resolveVar(v, ctx));
}
    
      
    6. 
      
  6. 
        
    6
    Evaluate the RewriteCond guards
    
        
    Before a rule can fire, its conditions must pass. Interpolate the test string (%{HTTPS} → "on"/"off"), then regex-test it — honoring a leading ! negation — or handle the filesystem checks -f/-d. Multiple conds AND together unless a cond carries [OR].
    
        
    function evalCond(cond, ctx, prevMatch){
  const test = interpolate(cond.testString, ctx, prevMatch);
  let p = cond.condPattern, negate = false;
  if (p[0] === "!") { negate = true; p = p.slice(1); }

  let result, groups = null;
  if (p === "-f") result = ctx.fileExists;          // browser can't stat — you toggle it
  else if (p === "-d") result = ctx.dirExists;
  else { const m = test.match(new RegExp(p, cond.flags.NC ? "i" : "")); result = !!m; groups = m; }

  return { test, result: negate ? !result : result, groups };
}
    
      
    7. 
      
  7. 
        
    7
    Redirect or rewrite?
    
        
    The single most important classification. A Redirect/RedirectMatch is always external. A RewriteRule is an internal rewrite — unless it has an [R] flag, or its target is an absolute http(s):// URL, in which case Apache forces a browser redirect. [F] and [G] short-circuit to 403/410.
    
        
    function classify(rule, target){
  if (rule.flags.F) return "forbidden";              // 403
  if (rule.flags.G) return "gone";                   // 410
  if (rule.type !== "rewrite") return "redirect";    // Redirect / RedirectMatch
  if (rule.flags.R) return "redirect";               // [R] or [R=301]
  if (/^https?:\/\//i.test(target)) return "redirect"; // absolute URL forces it
  return "rewrite";                                  // the default: browser URL unchanged
}
    
      
    8. 
      
  8. 
        
    8
    Run the ruleset in order — honor [L]
    
        
    Now replay: walk the rules top to bottom. Skip a rule if its conds fail or its pattern misses. When one fires, record the outcome; a redirect ends processing immediately, and an [L] flag stops the loop too. Everything after a stop is marked "skipped" — which is exactly how a misplaced catch-all reveals itself.
    
        
    function execute(rules, ctx){
  let path = ctx.path, stopped = false, first = -1, trace = [];
  rules.forEach((rule, i) => {
    if (stopped) return trace.push({ i, rule, state: "after-L" });
    const c = evalConds(rule.conds, ctx);
    if (!c.passed) return trace.push({ i, rule, state: "cond-failed" });
    const r = matchRule(rule.pattern, rule.flags, path);
    if (!r.match) return trace.push({ i, rule, state: "no-match" });

    const target = applySub(rule.substitution, r.match, c.lastMatch, ctx);
    const kind = classify(rule, target);
    if (first === -1) first = i;
    trace.push({ i, rule, state: "fired", target, kind, groups: r.match });
    if (kind === "redirect" || rule.flags.L) stopped = true;  // [L] = last
  });
  return { trace, first };
}

  9. 
        
    9
    Render the verdict + the trace
    
        
    The output is judgment, not just a match. Headline the first rule that fired — its number, its captured groups, the substituted target — and translate the kind into plain English: a rewrite keeps the address bar and serves other content; a 301 tells the browser to change URL permanently. Then list every rule with a status badge so the order is visible at a glance.
    
        
    function verdictText(kind, status, target){
  if (kind === "rewrite")   return `Internal rewrite → server serves "${target}", URL stays put`;
  if (kind === "redirect")  return `${status} redirect → browser navigates to "${target}"`;
  if (kind === "forbidden") return "403 Forbidden — request blocked";
  if (kind === "gone")      return "410 Gone — resource intentionally removed";
  return "No rule matched — request passes through unchanged";
}
