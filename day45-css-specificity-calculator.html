🎯 CSS Specificity Calculator — type a selector, watch it tokenize into the (a,b,c) triple, then pit two selectors against each other and see which one wins and exactly why — real selector parsing, no library

Two CSS rules fight over one element. Who wins? Stop guessing.

When two CSS rules both target the same element, the browser doesn't pick the last one blindly — it scores each selector's specificity and the higher score wins. That score is a triple (a, b, c): a counts #id selectors, b counts classes, [attributes] and :pseudo-classes, and c counts elements and ::pseudo-elements. The universal * and combinators (> + ~ space) count nothing. Type any selector below and this tool really tokenizes it — walks it character by character — to compute the triple and show what each token contributed. Then it compares your two selectors column-by-column and declares the winner. All of it runs in your browser; nothing is faked.

Five things people get wrong about specificity

1. It is NOT a base-10 number. (0,1,0) beats (0,0,11) — one class outranks eleven elements. You compare column by column: a first, then b, then c. A bigger later column can never overtake a smaller earlier one. 2. The universal * and combinators add nothing. * > body ~ .x + p scores the same as body .x p — the *, >, ~, + and descendant spaces are all zero; only the actual simple selectors count. 3. :not(), :is() and :has() are transparent. The pseudo-class itself adds nothing; it contributes the specificity of its most specific argument. So :is(#a, .b) is worth (1,0,0) — the #a. :where() is the exception: it is always zero. 4. Inline styles and !important live above the game. A style="" attribute behaves like (1,0,0,0) — a fourth, higher column that beats any selector. And !important jumps the whole cascade: a low-specificity !important rule still wins. 5. A tie is broken by source order. When two selectors compute to the exact same triple, the one written last in the CSS wins — specificity only decides when the scores differ.

🔨 Build it yourself

    
A specificity calculator sounds like it needs a real CSS parser — it doesn't. Specificity is just three counters: how many IDs, how many classes/attributes/pseudo-classes, how many elements/pseudo-elements. So the whole engine is a small tokenizer that walks the selector left-to-right, recognises each kind of simple selector, and bumps the right counter. Combinators and * bump nothing. The only genuinely clever bits are the functional pseudo-classes — :is(), :not(), :has() take the specificity of their most specific argument (so you recurse), and :where() is always zero. Get the tokenizer right and the (a,b,c) triple falls out, the comparison is three ifs, and the whole thing is maybe 60 lines of honest code — no library, no regex-only hacks that break on [href="a>b"]. Here is the entire engine, one step at a time.

    
    
      
  1. 
        
    1
    Specificity is three counters, not one number
    
        
    The whole state is a triple {a, b, c}. a = ID selectors, b = classes + attribute selectors + pseudo-classes, c = type (element) selectors + pseudo-elements. Everything the tokenizer does is decide which counter a token bumps. Comparing later is column-first: a, then b, then c.

const spec = { a: 0, b: 0, c: 0 };

//   b = .class  [attr]  :pseudo-class
//   c = element  ::pseudo-element
//   *  and combinators (> + ~ space) bump nothing

    Walk the selector character by character
    
        
    A regex like /\.[\w-]+/g looks tempting but breaks the moment an attribute value contains a dot or a bracket ([data-x=".foo]"]). A tiny hand-written scanner is both simpler and correct: look at the first character of each token to know its kind, then consume to the end of that token. An identifier is letters, digits, - and _.
    
        
    const isIdent = ch => /[\w-]/.test(ch);   // \w = [A-Za-z0-9_]

    3
    IDs → a, classes → b, types → c
    
        
    The three easy cases. A # starts an ID (bucket a). A . starts a class (bucket b). A bare identifier is a type/element selector (bucket c). In each case, consume the leading sigil then the run of identifier characters that names it.
    
        
    if (ch === '#'){                       // #id  -> a
  let j = i+1; while (isIdent(sel[j])) j++;
  out.push({ text: sel.slice(i,j), bucket:'a' });  i = j; continue;
}
if (ch === '.'){                       // .class -> b
  let j = i+1; while (isIdent(sel[j])) j++;
  out.push({ text: sel.slice(i,j), bucket:'b' });  i = j; continue;
}
if (isIdent(ch)){                      // div, a, h1 -> c
  let j = i; while (isIdent(sel[j])) j++;
  out.push({ text: sel.slice(i,j), bucket:'c' });  i = j; continue;
}

  4. 
        
    4
    Attributes → b, universal & combinators → 0
    
        
    An attribute selector [...] counts as b — but you must read to the matching ] while respecting quotes, so [href="a]b"] doesn't fool you. The universal *, the combinators > + ~ and the descendant space are all real tokens that contribute zero — record them so the breakdown can show them, but they bump no counter.
    
        
    if (ch === '['){                       // [attr] -> b  (respect quotes)
  let j = i+1, q = null;
  while (j < sel.length){
    const c = sel[j];
    if (q){ if (c === q && sel[j-1] !== '\\') q = null; }
    else if (c === '"' || c === "'") q = c;
    else if (c === ']') break;
    j++;
  }
  out.push({ text: sel.slice(i, j+1), bucket:'b' });  i = j+1; continue;
}
if (ch === '*'){ out.push({text:'*', bucket:'0'}); i++; continue; }          // universal
if ('>+~'.includes(ch)){ out.push({text:ch, bucket:'0'}); i++; continue; }   // combinator
if (/\s/.test(ch)){ out.push({text:'␣', bucket:'0'}); i++; continue; }       // descendant

  5. 
        
    5
    Pseudo-classes → b, pseudo-elements → c
    
        
    A single colon is a pseudo-class (:hover, :first-child) → b. A double colon is a pseudo-element (::before) → c. Four legacy names — :before :after :first-line :first-letter — are pseudo-elements even with one colon, so special-case them to c. If the pseudo is functional (name(...)), read its balanced parentheses too.
    
        
    const LEGACY_PE = ['before','after','first-line','first-letter'];

if (ch === ':'){
  const dbl = sel[i+1] === ':';
  let k = i + (dbl ? 2 : 1), s = k;
  while (isIdent(sel[k])) k++;
  const name = sel.slice(s, k).toLowerCase();
  let arg = null;
  if (sel[k] === '('){ const r = readParens(sel, k); arg = r.inner; k = r.end; }
  const text = sel.slice(i, k);

  if (dbl || LEGACY_PE.includes(name))  out.push({text, bucket:'c'});   // ::el -> c
  else if (name === 'where')            out.push({text, bucket:'0'});   // :where() -> 0
  else if (['is','not','has'].includes(name))
       out.push({text, bucket:'fn', add: mostSpecific(arg)});          // step 6
  else out.push({text, bucket:'b'});                                    // :hover, :nth-child ...
  i = k; continue;
}
    
      
    6. 
      
  6. 
        
    6
    :is() / :not() / :has() — recurse for the most specific argument
    
        
    These three are "transparent": the pseudo-class adds nothing of its own, it contributes the specificity of its most specific argument. Split the argument on top-level commas, score each argument selector with the very same engine, and keep the max. That recursion is why the tokenizer returns a callable score().
    
        
    function score(sel){                    // tokenize + sum
  let a=0,b=0,c=0;
  for (const t of tokenize(sel)){
    if (t.bucket==='a') a++;
    else if (t.bucket==='b') b++;
    else if (t.bucket==='c') c++;
    else if (t.bucket==='fn'){ a+=t.add.a; b+=t.add.b; c+=t.add.c; }
  }
  return { a, b, c };
}
function mostSpecific(argList){          // ":is(#a, .b, c)" -> {1,0,0}
  let best = { a:0, b:0, c:0 };
  for (const part of splitTopComma(argList))
    if (cmp(score(part), best) > 0) best = score(part);
  return best;
}
    
      
    7. 
      
  7. 
        
    7
    Compare column by column — a, then b, then c
    
        
    This is the step everyone gets wrong by treating the triple as a number. You compare a first; only if the a's tie do you look at b; only then c. So (0,1,0) beats (0,0,99). A positive result means the first selector wins; zero is a tie, broken later by source order.
    
        
    function cmp(x, y){
  if (x.a !== y.a) return x.a > y.a ? 1 : -1;   // IDs decide first
  if (x.b !== y.b) return x.b > y.b ? 1 : -1;   // then classes/attrs/pseudo-classes
  if (x.c !== y.c) return x.c > y.c ? 1 : -1;   // then elements
  return 0;                                     // exact tie -> source order wins
}
cmp(score('#id'), score('.a.b.c.d.e.f'));  //  1  -> #id wins, one ID > six classes

  8. 
        
    8
    The two things that sit ABOVE specificity
    
        
    Specificity only decides among normal, selector-based declarations. Two rungs sit above it. An inline style="" attribute behaves like a fourth, higher column — think (1,0,0,0) — beating any selector. And !important lifts a declaration out of the normal cascade entirely: an !important rule beats a non-important one no matter how low its specificity. So the real precedence is: !important → inline → specificity (a,b,c) → source order.
    
        
    function wins(A, B){                      // full author-cascade precedence
  if (A.important !== B.important) return A.important ? 'A' : 'B';  // 1. !important
  if (A.inline    !== B.inline)    return A.inline    ? 'A' : 'B';  // 2. inline (1,0,0,0)
  const c = cmp(A.spec, B.spec);                                    // 3. specificity
  if (c !== 0) return c > 0 ? 'A' : 'B';
  return 'source-order';                                           // 4. later wins
}
