VARY — THE HEADER THAT LEAKS

A cache keyed only on URL will hand a gzip body to a client that cannot decode it, or an English page to a French speaker — and with Vary: Cookie on a personalised page, one user's response to another. A cache answers one question: may I serve this without asking?


      
Everything in HTTP caching is that question. The answer has two halves — is the stored
      response still fresh, and if not, can I cheaply revalidate it.


      

        
fresh  ⟺  current_age < freshness_lifetime

  3. Expires − Date

  4. a heuristic — typically 10% of (Date − Last-Modified)
    5. 
      

      
That last one surprises people: a response with no caching headers at all is still
      cacheable, and a CDN may hold it for hours. "I didn't set a cache header" is not the same as
      "it will not be cached".


      
current_age is not "now minus Date"

      
This is the part that gets skipped, and it is the reason for stale-looking bugs behind
      proxies. RFC 9111 computes:

      
apparent_age    = max(0, response_time − date_value)
corrected_age   = max(apparent_age, age_value)          // trust the bigger one
resident_time   = now − response_time
current_age     = corrected_age + resident_time

      
Two consequences. A response that spent 50 seconds in an upstream CDN arrives with
      Age: 50 and, under max-age=60, is fresh for 10 more
      seconds, not 60. And a slow request inflates apparent_age, so a response
      can be born already half-expired. Set the delay slider on the SIMULATE tab and watch the first
      request come back stale before it is even stored.


      
no-cache ≠ no-store

      

        
no-cache means "store it, but ask me before every
        use". The response is written to disk. no-store means "never
        write it down" — that is the one for the bank statement. Shipping
        no-cache when you meant no-store leaves private content sitting in
        a shared cache, and it is the single most common mix-up in this whole area.

      


      
Revalidation is the cheap path, not the failure path

      
Stale does not mean "download it again". If you stored an ETag, send
      If-None-Match; the server compares and replies 304 Not Modified with
      no body. You pay one round-trip and zero bytes of payload, and the cache
      refreshes its stored response with the new headers.

      
The counters on the SIMULATE tab separate revalidations from full misses for exactly this
      reason — a cache with a 0% "hit rate" that is doing nothing but 304s is performing fine.


      
Vary, and the cache key

      
The cache key is not the URL. It is the URL plus the request headers named in
      Vary. Get this wrong and you do not get a slow site, you get a
      wrong one: compressed bodies to clients that asked for none,
      or — with Vary: Cookie — one user's page served to another.

      
Vary: * means the response is effectively uncacheable. And every value you add
      multiplies the number of stored variants, which is how a cache with a 99% configured hit rate
      ends up never hitting anything.


    

  






  

    


      
🔨 Build it yourself


      
1. Parse Cache-Control properly

      
It is a comma-separated list where some members carry values and some do not, values may be
      quoted, and names are case-insensitive. Splitting on "," and comparing strings
      will bite you on max-age="60".

      
function parseCC(v){
  const out = {};
  for (const part of String(v || "").split(",")){
    const [rawK, ...rest] = part.trim().split("=");
    if (!rawK) continue;
    const k = rawK.toLowerCase();
    let val = rest.join("=").trim();
    if (val.startsWith('"') && val.endsWith('"')) val = val.slice(1, -1);
    out[k] = val === "" ? true : (isNaN(+val) ? val : +val);
  }
  return out;
}


      
2. freshness_lifetime, in the RFC's order

      
function freshnessLifetime(h, shared){
  const cc = parseCC(h["cache-control"]);
  if (shared && typeof cc["s-maxage"] === "number") return { s: cc["s-maxage"], why: "s-maxage" };
  if (typeof cc["max-age"] === "number")              return { s: cc["max-age"],   why: "max-age" };
  if (h["expires"] && h["date"])
    return { s: (Date.parse(h["expires"]) - Date.parse(h["date"])) / 1000, why: "Expires - Date" };
  if (h["last-modified"] && h["date"])                       // the heuristic
    return { s: 0.1 * (Date.parse(h["date"]) - Date.parse(h["last-modified"])) / 1000,
             why: "heuristic, 10% of Date - Last-Modified" };
  return { s: 0, why: "nothing to go on" };
}


      
3. current_age — write it exactly as specified

      
function currentAge(h, requestTime, responseTime, now){
  const dateValue = Date.parse(h["date"]) / 1000;
  const ageValue  = +(h["age"] || 0);
  const apparentAge   = Math.max(0, responseTime - dateValue);
  const correctedAge  = Math.max(apparentAge, ageValue);
  const residentTime  = now - responseTime;
  return correctedAge + residentTime;
}

      
Do not simplify this. Every term is carrying a real case, and the shortcut
      now - Date silently drops both the upstream Age and the transit time.


      
4. The decision, as one function

      
function decide(entry, req, now, shared){
  const cc = parseCC(entry.headers["cache-control"]);
  if (cc["no-store"]) return { action: "MISS", why: "no-store: never written down" };
  if (!varyMatches(entry, req)) return { action: "MISS", why: "Vary key mismatch" };

  const age = currentAge(entry.headers, entry.requestTime, entry.responseTime, now);
  const fl  = freshnessLifetime(entry.headers, shared).s;

  if (cc["no-cache"]) return { action: "REVALIDATE", why: "no-cache: must ask every time" };
  if (age < fl)       return { action: "HIT", why: `age ${age|0}s < lifetime ${fl|0}s` };
  if (entry.headers["etag"] || entry.headers["last-modified"])
    return { action: "REVALIDATE", why: `stale by ${(age-fl)|0}s, but revalidatable` };
  return { action: "MISS", why: "stale and nothing to revalidate with" };
}


      
5. The Vary key

      
function varyKey(varyHeader, reqHeaders){
  const names = String(varyHeader || "").split(",").map(s => s.trim().toLowerCase()).filter(Boolean);
  if (names.includes("*")) return null;                  // never reusable
  return names.map(n => n + "=" + (reqHeaders[n] || "")).join("&");
}

      
Store this alongside the response and compare it on every lookup. A cache that skips it is
      not slightly wrong, it is serving the wrong body — which the SIMULATE tab counts for
      you.
