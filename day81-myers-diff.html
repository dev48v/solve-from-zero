SOLVEFROMZERO · DAY 81

Myers diff — the shortest edit script, found by walking a graph diagonally, and why the shortest one is not always the one you want.

Two files in, one minimal list of edits out

Every diff you have ever read is the answer to one question: what is the shortest sequence of deletions and insertions that turns the old file into the new one? Myers' 1986 algorithm answers it by treating the two files as the axes of a grid and finding the cheapest path across — where moving diagonally, on a line both files share, is free.

D is not a guess — it is forced by the common subsequence

For two inputs of length N and M sharing a longest common subsequence of length L, the shortest edit script has exactly D = N + M − 2L steps. Every line that is not common must be either deleted or inserted, and no line is touched twice. The table checks that identity on every example, with L computed by a completely different method.

Shortest is not the same as readable

This is the part that surprises people. Several edit scripts can be equally short, and they are not equally good to read. The same minimal distance can be spent as one tidy block or scattered across many — and a diff tool that only minimises D has no opinion about which you get.

The edit graph

Lay the old file along the x axis and the new file along the y. You start at (0,0) and must reach (N,M). Moving right deletes a line of the old file and costs 1. Moving down inserts a line of the new file and costs 1. Where a[x] === b[y] you may move diagonally for free. The shortest edit script is the cheapest path, and "cheapest" counts only the non-diagonal moves.

Why walk by D rather than by position

The trick is the order of the search. Rather than exploring the grid cell by cell, Myers asks: how far can I get using exactly D edits? For each D it keeps only the furthest-reaching point on each diagonal — one number per diagonal, not a whole row — and stops the first time one of them reaches the corner. Because D only ever increases, the first arrival is minimal by construction.

That makes the cost O((N+M)D) rather than O(NM). For the files people actually diff, D is small and the difference is enormous. For files with nothing in common D grows until the two converge — and then keep going, until Myers is doing more work than the table it replaced. Recovering the script, not just its length

Knowing D is not a diff. To produce the edits you must remember the furthest-reaching array V at every value of D, then walk backwards from the corner, at each step asking which predecessor could have reached here. That is why the implementation snapshots V per round instead of overwriting one array.
