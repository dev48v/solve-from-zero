Every file on a Unix system carries nine permission bits — read, write, execute for the owner, the group, and everyone else — plus three special bits. People memorise magic numbers like 644 and 755 without ever seeing that the digit is just 4 + 2 + 1. Five things people get wrong about chmod

1. The digit is just 4 + 2 + 1. There is no lookup table to memorise: read is 4, write is 2, execute is 1, and you add the ones that are on. 7 = 4+2+1 (all), 5 = 4+1 (read+exec), 6 = 4+2 (read+write). 2. 777 is almost never what you want. It lets anyone on the machine write to the file. Web files are usually 644, directories and scripts 755; private keys need 600. 3. Execute on a directory ≠ execute on a file. On a file, execute means "run it as a program". On a directory it means "you may enter/traverse it" — a dir with read but no execute lists names but lets you open nothing. 4. The leading 4th digit is the special bits. 4755 sets setuid, 2755 setgid, 1777 the sticky bit — and they show up as s/t in the execute slot of the symbolic string (upper-case S/T when the underlying execute bit is off). 5. Symbolic mode is relative, numeric is absolute. chmod 644 f sets the mode exactly; chmod u+x f only adds one bit to whatever is already there. This calculator always shows the absolute result.

🔨 Build it yourself

    
A permissions calculator feels like it should be a big lookup table — it isn't. A Unix mode is just bits, and every representation (the octal 755, the symbolic rwxr-xr-x, the ticked checkboxes) is a different view of the same bits. So the whole tool is: keep one source-of-truth mode, and write pure functions that compose bits into a number/string and parse a number/string back into bits. Read is 4, write is 2, execute is 1; OR them together to make a digit, AND against them to read a digit apart. Get those two directions right and the two-way sync is almost free — change any input, rebuild the mode, re-render everything from it. Here is the entire engine, one honest step at a time — real bit arithmetic, no library.

    
    
      
  1. 
        
    1
    Model the mode as bits
    
        
    A file mode has three permission classes — user, group, other — and each is three booleans: read, write, execute. Plus three special bits (setuid, setgid, sticky). That's the entire state. One plain object is the single source of truth; every display is derived from it, and every input rewrites it.
    
        
    // the whole state of a file's permissions
const mode = {
  special: { setuid:false, setgid:false, sticky:false },
  u: { r:true,  w:true,  x:true  },   // owner
  g: { r:true,  w:false, x:true  },   // group
  o: { r:true,  w:false, x:true  },   // everyone else
};
    
      
    2. 
      
  2. 
        
    2
    One class → one octal digit (4·2·1)
    
        
    The magic numbers are just weighted sums. Read is worth 4, write 2, execute 1 — because they're the three bits of a single octal digit (binary 100, 010, 001). Bitwise-OR the ones that are on and you get 0–7. rwx → 4|2|1 = 7; r-x → 4|1 = 5.
    
        
    function classToDigit(c){
  return (c.r ? 4 : 0) | (c.w ? 2 : 0) | (c.x ? 1 : 0);
}
classToDigit({r:true, w:true,  x:true })  // 7  (rwx)
classToDigit({r:true, w:false, x:true })  // 5  (r-x)
classToDigit({r:true, w:true,  x:false}) // 6  (rw-)
    
      
    3. 
      
  3. 
        
    3
    Compose the full octal string
    
        
    Do the same for the special bits (setuid 4, setgid 2, sticky 1) to get a leading digit, then concatenate: special · user · group · other. Show the 4th digit only when a special bit is set — 755 stays three digits, 4755 becomes four.
    
        
    function specialToDigit(s){
  return (s.setuid ? 4 : 0) | (s.setgid ? 2 : 0) | (s.sticky ? 1 : 0);
}
function toOctal(mode){
  const sp = specialToDigit(mode.special);
  const three = `${classToDigit(mode.u)}${classToDigit(mode.g)}${classToDigit(mode.o)}`;
  return sp ? `${sp}${three}` : three;   // 755  or  4755
}
    
      
    4. 
      
  4. 
        
    4
    Compose the symbolic string
    
        
    The rwxr-xr-x form is three triads glued together. For a plain class each slot is its letter or a dash. The execute slot is special: when a special bit applies to that class it shows s (setuid/setgid) or t (sticky) instead of x — and an upper-case S/T if the execute bit underneath is actually off.
    
        
    function triad(c, special){          // special: 's' | 't' | null
  const set   = special === 't' ? 't' : 's';
  const unset = special === 't' ? 'T' : 'S';
  const x = special ? (c.x ? set : unset) : (c.x ? 'x' : '-');
  return (c.r ? 'r' : '-') + (c.w ? 'w' : '-') + x;
}
function toSymbolic(m){
  return triad(m.u, m.special.setuid ? 's' : null)
       + triad(m.g, m.special.setgid ? 's' : null)
       + triad(m.o, m.special.sticky ? 't' : null);
}
    
      
    5. 
      
  5. 
        
    5
    Parse an octal string back to bits
    
        
    The reverse direction is where "real bit math" earns its keep. Validate 3–4 octal digits, peel off the optional leading special digit, then AND each digit against 4/2/1 to recover the three booleans. 7 & 4 is truthy → read is on; 5 & 2 is 0 → write is off.
    
        
    function digitToClass(d){
  return { r: !!(d & 4), w: !!(d & 2), x: !!(d & 1) };
}
function parseOctal(str){
  str = str.trim();
  if (!/^[0-7]{3,4}$/.test(str)) return null;       // reject garbage
  const sp = str.length === 4 ? +str[0] : 0;
  const [u, g, o] = str.slice(-3).split('').map(Number);
  return {
    special: { setuid:!!(sp&4), setgid:!!(sp&2), sticky:!!(sp&1) },
    u: digitToClass(u), g: digitToClass(g), o: digitToClass(o),
  };
}
    
      
    6. 
      
  6. 
        
    6
    Parse a symbolic string back to bits
    
        
    Accept the 9-char form (or 10 with a leading file-type char, as ls -l prints). Split into three triads; read/write are their letter-or-dash, and the execute slot decodes both the execute bit and whether the class carries a special bit: x→exec on, s/t→exec on + special, S/T→exec off + special.
    
        
    function parseTriad(t, setChar, unsetChar){
  const r = t[0] === 'r', w = t[1] === 'w', c = t[2];
  if (c === 'x')        return { r, w, x:true,  special:false };
  if (c === '-')        return { r, w, x:false, special:false };
  if (c === setChar)    return { r, w, x:true,  special:true  };  // s or t
  if (c === unsetChar)  return { r, w, x:false, special:true  };  // S or T
  return null;                                                    // invalid
}
function parseSymbolic(str){
  str = str.trim();
  if (str.length === 10) str = str.slice(1);        // drop the -/d type char
  if (!/^[rwxsStT-]{9}$/.test(str)) return null;
  const U = parseTriad(str.slice(0,3), 's', 'S');
  const G = parseTriad(str.slice(3,6), 's', 'S');
  const O = parseTriad(str.slice(6,9), 't', 'T');
  if (!U || !G || !O) return null;
  return {
    special: { setuid:U.special, setgid:G.special, sticky:O.special },
    u:{r:U.r,w:U.w,x:U.x}, g:{r:G.r,w:G.w,x:G.x}, o:{r:O.r,w:O.w,x:O.x},
  };
}

  7. 
        
    7
    Wire the two-way sync
    
        
    One mode is the truth; one render() paints every field from it. Each input handler rebuilds mode from its own value, then re-renders — skipping the field the user is actively typing in so the cursor doesn't jump. Because compose and parse are exact inverses, the grid, the octal box and the symbolic box can never disagree.
    
        
    function render(skip){
  if (skip !== 'checks')  writeCheckboxes(mode);
  if (skip !== 'octal')   octalInput.value    = toOctal(mode);
  if (skip !== 'symbolic')symbolicInput.value = toSymbolic(mode);
  paintCommand(mode); paintLsLine(mode); paintBreakdown(mode);
}
octalInput.oninput = () => {
  const m = parseOctal(octalInput.value);
  if (m) { mode = m; render('octal'); octalInput.classList.remove('bad'); }
  else   octalInput.classList.add('bad');
};

  8. 
        
    8
    Render the command, the ls -l line & the decimal
    
        
    The last mile is presentation. The command is literally chmod + the octal + the filename. The ls -l line prefixes the symbolic string with a file-type char (- for a file, d for a directory). And the "decimal" is a nice reminder that the octal really is a number — parseInt("755", 8) is 493.
    
        
    const octal = toOctal(mode);                     // "755"
cmdOut.textContent  = `chmod ${octal} ${filename}`;      // chmod 755 file.sh
lsPerm.textContent  = (isDir ? 'd' : '-') + toSymbolic(mode);  // -rwxr-xr-x
stDec.textContent   = parseInt(octal, 8);        // 493  (base-8 → base-10)

Composing runs one way (classToDigit with |, then concatenate the triads), parsing runs the other (& 4, & 2, & 1 to pull each bit back out), and because the two are exact inverses, a single source-of-truth mode plus a render() keeps the grid, the octal, the symbolic string and the chmod command in perfect agreement — type into any one and the rest follow.
