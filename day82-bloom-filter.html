SOLVEFROMZERO · DAY 82

Bloom filters — the false-positive formula everyone quotes is optimistic, and it is worst where the filter is smallest.

It never misses. It just lies in the other direction.

A Bloom filter is a bit array and k hash functions. Adding a key sets k bits; asking about a key checks those same bits. If any is zero the key was definitely never added. If all are one — it probably was. Probably is the entire subject.

The structure makes exactly one promise and it keeps it absolutely: there are no false negatives. Everything else is a rate you are choosing whether you realise it or not.

Four filters, 20,000 strangers tested against each. The last column is the one to look at: the measured rate against what the formula in the tutorials predicts.

Choosing k, and the column the formula ignores

More hashes means more bits to clear before a stranger gets through — but also more bits set per key, so the array saturates faster. The optimum is (m/n) · ln 2, and the curve around it is flat.

The textbook formula is wrong, and wrong in the dangerous direction

p = (1 - e-kn/m)k assumes the k bits a key sets are independent. They are not. One key's own probes can land on each other, so it may set fewer than k bits. The formula is a limit, and below are five filters at a fixed m/n ratio of 6.4 where only the size changes.

The exact rate conditions on how many bits are really set, rather than assuming. The error is small — but it is optimistic at small m, which is the wrong way round for a structure chosen to bound a risk.

And the rate only holds if the hash avalanches

Every number above assumes the probes land uniformly. Swap in a hash whose low bits carry structure — and a power-of-two array uses only the low bits — and the filter you measure is not the filter you computed.

k hashes from two, and the bit that makes it work

Computing k independent hashes is wasteful. Kirsch–Mitzenmacher says two are enough: gi(x) = h1 + i·h2. The trap is h2 being even when m is a power of two — then the step never changes parity and half the array is unreachable. One | 1 fixes it.
