A .gitignore is not a list of files. It is a program, and the last rule to speak wins.

Everybody reads a .gitignore top to bottom like a shopping list and assumes the first rule that matches decides. It is the opposite: git walks every pattern, remembers the last one that matched, and that one decides — which is the only reason ! negation can work at all. Then a second rule quietly overrides the first: git does not test paths, it walks directories, and it never walks into a directory it has already decided to ignore. So node_modules/ followed by !node_modules/patched.js does exactly nothing — the file is unreachable, not un-matched. This page implements the real matcher: the line parser with its escapes and its trailing-space rule, a glob compiler where * stops at a slash and ** does not, the anchoring rule, directory-only patterns, nested ignore files, and the ancestor walk that produces the trap. Every verdict below points at the exact file and line number that produced it.

Where else git looks

Four sources feed the same matcher, and they are consulted in a fixed order of decreasing precedence. Highest: patterns passed on the command line (git ls-files --exclude). Then every .gitignore from the path's own directory upward — deeper wins, which is what the tabs on the left model. Then $GIT_DIR/info/exclude, a per-clone file that is never committed, for the junk only your machine makes. Lowest: the file named by core.excludesFile, your global ignore list, which is where .DS_Store and editor droppings actually belong rather than in every repo you touch.

git config --global core.excludesFile ~/.gitignore_global
echo ".DS_Store"  >> ~/.gitignore_global
echo "scratch.md" >> .git/info/exclude   # local only, never committed
Prove it against real git

Everything on this page has an oracle you already have installed. check-ignore -v prints the source file, line number and pattern that decided — the same three things this page prints in the "Decided by" column.

$ git check-ignore -v --no-index node_modules/patched.js
.gitignore:11:node_modules/    node_modules/patched.js

$ git status --porcelain -uall --ignored=matching
!! node_modules/patched.js
?? src/app.log
Five things worth knowing about .gitignore

1. It only hides files git is not already tracking. Adding .env to .gitignore after you committed .env changes nothing at all — the file is in the index, and the index outranks every ignore rule. The fix is git rm --cached .env, which deletes it from the index while leaving it on disk; only then does the pattern start applying. This is why "I added it to gitignore and it still shows up" is the single most common git question ever asked. 2. The last matching pattern wins, not the first. Git evaluates every line and keeps the most recent match, which is the whole mechanism behind !: a negation only works if it appears after the rule it is undoing. Reorder two lines and you flip the answer, which makes a .gitignore genuinely order-dependent in a way a list of filenames never is. 3. You cannot re-include a file inside an excluded directory. Git does not test every path against every pattern; it walks the tree and prunes. If node_modules/ is excluded, git never opens the directory, so !node_modules/patched.js is a line that can never be reached. The documented workaround is to unignore at directory granularity first — /* then !/keep/ — so the walk can still get inside. 4. A slash changes the meaning of the whole line. build matches a file or directory named build at any depth, because a pattern with no slash is matched against the basename only. Add a slash anywhere — /build, src/build — and the pattern is anchored to the directory holding that .gitignore. And build/ with a trailing slash still matches at any depth, but only directories. 5. * stops at a slash and ** does not. src/*.js never matches src/util/a.js, because the glob is path-aware; you need src/**/*.js. And the three ** shapes mean three different things: leading **/x is "at any depth", trailing x/** is "everything inside x", and middle a/**/b is "b under a, zero or more directories down".

🔨 Build it yourself

    
A gitignore engine is three layers. A line parser that turns text into rule objects, dealing with comments, escapes and the trailing-space rule. A glob compiler that turns one pattern into a matcher which respects path boundaries — * stops at /, ** does not. And a walker that tests a path's ancestors before the path itself and stops at the first excluded directory, which is where every surprising gitignore behaviour comes from. Here it is, step by step.

    
    
      
  1. 
        
    1
    The line parser — blanks, comments, and one weird space rule
    
        
    A blank line matches nothing and exists only as a separator. A line whose first raw character is # is a comment — checked before any trimming, which is why \#draft.md is a pattern and not a comment. Trailing spaces are stripped, but only literal spaces (never tabs), and a backslash cancels the strip so foo\  really does target a file ending in a space. Leading whitespace is never stripped, so an accidentally indented rule targets a filename that starts with spaces and silently does nothing.
    
        
    function trimTrailingSpaces(s){
  let lastSpace = -1;
  for (let i = 0; i < s.length; i++) {
    const c = s.charAt(i);
    if (c === " ") { if (lastSpace < 0) lastSpace = i; continue; }
    if (c === "\\") { i++; if (i >= s.length) return s; }  // \ escapes, incl. "\ "
    lastSpace = -1;
  }
  return lastSpace >= 0 ? s.slice(0, lastSpace) : s;
}

if (raw === "")            return { kind: "blank" };
if (raw.charAt(0) === "#") return { kind: "comment" };   // RAW first char
    
      
    2. 
      
  2. 
        
    2
    Peel off the two prefix/suffix flags
    
        
    A leading ! makes the rule a negation and is removed from the body; a literal bang is written \!, which the compiler later unescapes. A single trailing / sets "directory only" and is removed. Order matters: the bang comes off first, so !build/ is a negated directory-only rule. Only one trailing slash is consumed, so foo// ends up as the pattern foo/, which matches nothing at all — a real typo that produces a silently dead rule.
    
        
    let body = trimTrailingSpaces(raw), negated = false, dirOnly = false;
if (body.charAt(0) === "!") { negated = true; body = body.slice(1); }
if (body.endsWith("/"))     { dirOnly = true; body = body.slice(0, -1); }
if (body === "") return { kind: "blank" };     // "!" or "/" alone

// anchoring: does ANY raw slash survive in the body?
const anchored = body.indexOf("/") !== -1;
const matchBody = body.charAt(0) === "/" ? body.slice(1) : body;
    
      
    3. 
      
  3. 
        
    3
    Anchored or basename — the single most important branch
    
        
    After the trailing slash is gone, scan the body for a /. If there is none, the rule is matched against the basename of the path and therefore fires at any depth. If there is one anywhere — leading, middle, it does not matter — the rule is matched against the whole path relative to the directory holding that .gitignore, and a leading slash is then just noise that gets stripped. That is the entire difference between build (any depth) and /build (root only), and it is why docs/*.md quietly stops matching once you nest a folder.
    
        
    function patternMatches(p, path, isDir, baseDir){
  if (p.dirOnly && !isDir) return false;
  let rel = path;
  if (baseDir) {                                   // nested .gitignore
    if (path.slice(0, baseDir.length + 1) !== baseDir + "/") return false;
    rel = path.slice(baseDir.length + 1);
  }
  if (p.anchored) return p.regex.test(rel);        // whole relative path
  return p.regex.test(rel.slice(rel.lastIndexOf("/") + 1));  // basename only
}
    
      
    4. 
      
  4. 
        
    4
    Compiling one path segment
    
        
    Within a single segment, * becomes [^/]* and ? becomes [^/] — never . and never .*, because the glob is path-aware and a wildcard must not swallow a directory boundary. A backslash escapes the next character into a literal, which is how \#, \! and \* survive. Everything else is escaped for the regex engine, so a dot in *.log is a real dot rather than "any character".
    
        
    function segGlob(s){
  let out = "";
  for (let i = 0; i < s.length; i++) {
    const c = s.charAt(i);
    if (c === "\\" && i + 1 < s.length) { out += escRe(s.charAt(++i)); continue; }
    if (c === "*") { out += "[^/]*"; continue; }   // NOT ".*"
    if (c === "?") { out += "[^/]";  continue; }   // NOT "."
    if (c === "[") { const k = parseClass(s, i);
                     if (k) { out += k.re; i = k.next - 1; continue; } }
    out += escRe(c);
  }
  return out;
}
    
      
    5. 
      
  5. 
        
    5
    Character classes, including the negated kind
    
        
    Git supports full fnmatch bracket expressions: ranges like [a-z], explicit sets like [Tt], POSIX names like [[:digit:]], and negation with [!abc] — note the !, not the ^ a regex would use, though git accepts both. One rule is easy to miss: a bracket expression never matches a /, even if you literally put a slash inside it, so the compiled class gets a guard in front of it.
    
        
    function parseClass(s, i){                 // s[i] === "["
  let j = i + 1, neg = false;
  if (s.charAt(j) === "!" || s.charAt(j) === "^") { neg = true; j++; }
  let body = "", first = true, closed = false;
  while (j < s.length) {
    const c = s.charAt(j);
    if (c === "]" && !first) { closed = true; j++; break; }   // "[]]" is legal
    first = false;
    body += (c === "-" ? "-" : escClass(c));                  // keep ranges
    j++;
  }
  if (!closed) return null;                                   // stray "[" = literal
  return { re: "(?!/)[" + (neg ? "^" : "") + body + "]", next: j };
}
    
      
    6. 
      
  6. 
        
    6
    ** — one token, three meanings
    
        
    A ** is only special when it is an entire path segment; a**b is just two ordinary stars. As a segment it means "zero or more directories", which produces three shapes. Leading **/x matches x at any depth including the root, so the group must be allowed to repeat zero times. Trailing x/** matches everything inside x but never x itself, so it needs at least one character after the slash. Middle a/**/b matches a/b as well as a/p/q/b — the "zero directories" case is the one hand-rolled matchers usually get wrong.
    
        
    function compileGlob(body){
  const segs = splitSegments(body);
  let out = "", needSep = false;
  for (let i = 0; i < segs.length; i++) {
    const s = segs[i], last = i === segs.length - 1;
    if (/^\*\*+$/.test(s)) {
      if (last) { out += (needSep ? "/" : "") + ".+"; needSep = false; }   // x/**
      else      { out += (needSep ? "/" : "") + "(?:[^/]+/)*"; needSep = false; }
    } else { out += (needSep ? "/" : "") + segGlob(s); needSep = true; }
  }
  return new RegExp("^" + out + "$");
}

// "**/build"  -> ^(?:[^/]+/)*build$      any depth, incl. root
// "cache/**"  -> ^cache/.+$              inside cache, not cache itself
// "a/**/b"    -> ^a/(?:[^/]+/)*b$        zero or more dirs between
    
      
    7. 
      
  7. 
        
    7
    Last match wins — across a stack of files
    
        
    Evaluating a path means running every applicable rule and keeping the last one that matched, rather than returning early on the first hit. Applicable means: every .gitignore in an ancestor directory of the path, from the repository root downward. Iterating shallow-to-deep and overwriting the winner gives you both precedence rules for free — later lines beat earlier lines inside one file, and a deeper file beats a shallower one, because it simply runs last.
    
        
    function lastMatch(files, path, isDir){
  const dirs = ancestorDirs(path);        // "a/b/c.txt" -> ["", "a", "a/b"]
  let win = null;
  for (const d of dirs) {                 // shallow first...
    const f = files[d];
    if (!f) continue;
    for (const p of f.patterns)           // ...later lines overwrite earlier
      if (patternMatches(p, path, isDir, d)) win = p;
  }
  return win;                             // may be a NEGATION
}
    
      
    8. 
      
  8. 
        
    8
    The walk — where the parent-directory rule comes from
    
        
    This is the function that makes the engine correct instead of merely plausible. Git does not ask "does any pattern match this path"; it walks the tree and refuses to descend into an excluded directory. So the classifier tests each ancestor prefix as a directory first, and the instant one of them comes back excluded it stops and reports that ancestor's rule as the decider. Everything below an excluded directory is therefore ignored, unreachable, and invisible to any later negation.
    
        
    function classify(files, path, isDir){
  const segs = path.split("/");
  for (let i = 0; i < segs.length; i++) {
    const sub  = segs.slice(0, i + 1).join("/");
    const last = i === segs.length - 1;
    const win  = lastMatch(files, sub, last ? isDir : true);
    if (win && !win.negated)                       // an ancestor is excluded
      return { ignored: true, by: win, at: sub, viaParent: !last };
  }
  return { ignored: false, by: lastMatch(files, path, isDir), at: path };
}

  9. 
        
    9
    Detect the trap and say so out loud
    
        
    A tool that only answers "ignored: yes" is useless for the case people actually hit. When the walk stops at an ancestor, ask a second question the walk skipped: what would the path's own last match have been? If it would have been a negation, the user wrote a rule that can never fire, and you can say exactly that plus name the fix — unignore the directory first, then narrow inside it.
    
        
    if (res.viaParent) {
  const own = lastMatch(files, path, isDir);
  if (own && own.negated) {
    res.trapped = true;                    // "!" that can never be reached
    res.trapBy  = own;
    res.fix     = "unignore the directory first:  " + res.at + "/*\n"
                + "                               !" + path;
  }
}

    10
    Prove it — real git is the oracle
    
        
    This is one of the rare toys with a free reference implementation sitting on your machine. Generate a throwaway repo, write your patterns and a tree, then compare: git status --porcelain -uall --ignored=matching gives the verdict for every file, and git check-ignore -v --no-index gives the source file, line number and pattern that decided it. Assert both, and any disagreement is your bug rather than an opinion.
    
        
    const oracle = run("git status --porcelain -uall --ignored=matching");
for (const line of oracle.split("\n")) {
  const ignored = line.startsWith("!!");            // "??" = not ignored
  const path    = line.slice(3).trim();
  assert(classify(files, path, false).ignored === ignored, path);
}
