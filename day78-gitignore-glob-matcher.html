📂 A real ignore-file matcher — *.log, build/, !keep.log, **/tmp. The same handful of characters goes into a .gitignore, an rsync --exclude, a shell glob and a .dockerignore, and this implements all four from their own rules over one shared matcher, so the same pattern is read four ways and the answers sit side by side. Nothing is sampled: 10 patterns × 24 paths is an enumerated 240-cell grid and every figure is a count. 🔴 Not one of the ten patterns means the same thing in all four tools. Zero. The grid agrees on 212 of 240 cells — 88.33%, which sounds reassuring until you notice the disagreements are concentrated in the patterns people actually write. 🔴 *.log in a .dockerignore does not match src/app.log, because Docker anchors at the context root and git does not. 🔴 And the one that costs an afternoon: test/ followed by !test/fixtures/keep.log does nothing at all — git will not re-include a file whose parent directory is excluded, and it reports no error, no warning, and no sign that the second line was ignored.

Four real implementations, not four wrappers. git's basename-at-any-depth rule and its parent-exclusion rule, rsync's anchoring, a shell glob that will not cross a slash, and Docker's root-anchored match — each written from its own documented behaviour over one shared glob engine, so a difference in the table is a difference in the rules rather than a difference in libraries.

1. Every pair of tools disagrees, and by wildly different amounts

The closest two are a shell glob and .dockerignore, 3 cells of 240 — both anchor at the root, so they mostly agree. git and rsync are next at 4, both matching a bare pattern at any depth. The two families are far apart: git against a shell glob differs on 28. The intuition that “ignore syntax is ignore syntax” is right within a family and wrong across them, and nothing in the file tells you which one you are holding.

2. The anchoring rule, which is where most of it comes from

git treats a pattern with no slash as a basename pattern and matches it at any depth. Docker anchors everything at the context root. That single difference produces most of the grid.

*.log is the most-written ignore line there is. In git it catches src/deep/nested/app.log; in a .dockerignore it catches app.log and nothing below it. Both are correct, documented behaviour. Neither file format announces which one it is.

3. The negation that does nothing, silently

This is the one worth carrying away. You exclude a directory, then try to re-include one file inside it: 

test/                        <- excludes the directory itself
!test/fixtures/keep.log      <- never gets a chance to apply

🔴 The file stays ignored. git does not descend into an excluded directory, so the re-inclusion never gets a chance to apply — and a matcher that simply walks the pattern list in order, which is what most people picture, gets the opposite answer. There is no error and no warning.

And the obvious repair does not work either. Adding !test/fixtures/ changes nothing, because test itself is still excluded and git still never descends. The line that works is test/* — exclude the contents rather than the directory, so the walk continues and the negation gets a chance to apply. One character, and nothing in the file, the tool, or the output tells you which of the two you wrote.

What this covers and what it does not

The four engines implement the rules that produce the disagreements above: anchoring, basename matching, directory-only patterns, negation, globstar, and git's parent-exclusion rule. They are not complete reimplementations — nested .gitignore files, case-insensitive filesystems, core.excludesFile and rsync's per-directory merge files are all out of scope, and each of those is another way for two tools to differ. The claim is about the ten patterns and 24 paths in the grid, which is what the counts are over.

How it works

One recursive glob matcher underneath, with * refusing to cross a slash, ** special only as a whole path segment, and character classes with ranges and negation. The four tools are thin policies over it — which is the point, because it means a difference in the grid is a difference in the rules, not an artefact of four separate parsers. 

// git: no slash in the pattern means "match the basename at any depth"
const anchored = p.includes("/");
if (!anchored) return path.split("/").some((seg) => globMatch(p, seg));

// docker: always anchored at the context root
return globMatch(p, path);

Self-check

Runs on load. Several are controls: a claim that two tools disagree means nothing without the cases where they agree.
