🧬 JSON Structural Diff — a real, from-scratch semantic diff of two JSON documents: paste a before and an after, both are JSON.parse'd into real trees, then a recursive walker compares them node by node — type-aware (a number that became a string is a change, not a coincidence), order-insensitive for object keys (reordering keys is not a diff), and index-aligned for arrays — classifying every leaf and branch as added / removed / changed / unchanged, rendering a colour-coded collapsible tree (green add · red remove · amber change), a live summary count, and an emitted RFC 6902 JSON-Patch (op / path / value) whose paths are RFC 6901 JSON-Pointers · graceful parse-error handling with line & column · this compares meaning, not characters, so it is distinct from the Day-13 line diff-checker · vanilla JS, no library

Two JSON documents. What actually changed — not which lines moved.

A plain text diff treats JSON as lines of characters, so it lies about JSON: reformat a file, reorder two keys, or add a trailing comma and it screams that everything changed — even though the data is identical. A structural diff parses both sides into real trees and compares meaning. It walks the two trees together: at every object it compares the union of keys (so key order never matters), at every array it lines up elements by index, and at every leaf it checks both type and value. Each spot is labelled added, removed, changed or unchanged — and from those labels it can emit a machine-applyable RFC 6902 JSON-Patch that turns before into after. Everything runs in your browser, no library, nothing uploaded. Edit either side and the diff updates live.

Five things worth knowing about diffing JSON

1. A text diff is the wrong tool for JSON. Line-based diffs react to whitespace, indentation and key order — none of which change the data. Reformat a config file and a text diff lights up red; a structural diff correctly reports "nothing changed". 2. Key order is not information. {"a":1,"b":2} and {"b":2,"a":1} are the same object, so this tool compares the union of keys and never flags a reorder. 3. Type changes are real changes. The string "10" and the number 10 look alike but are different values — a change, not a match. null, {} and [] are all distinct too. 4. Arrays are the hard part. There is no canonical way to align two lists, so the simple, predictable choice is by index. That means an insert near the front cascades into a wall of "changed" — honest, but a reminder that array position carries meaning in JSON. 5. A diff can be executable. Once you know what changed, you can emit an RFC 6902 JSON-Patch — a list of add / remove / replace ops with JSON-Pointer paths — that any compliant library can apply to reproduce after from before.

🔨 Build it yourself

    
A structural JSON diff is one small recursive function. Given two values it asks: are they the same type? If not, it is a change. If both are objects, walk the union of their keys; if both are arrays, walk the indices; if both are primitives, compare them directly. Every descent extends a JSON-Pointer path by one segment, so a difference buried five levels deep still names its exact location — and those labelled locations turn straight into an RFC 6902 JSON-Patch. Here it is, step by step.

    
    
      
  1. 
        
    1
    Parse both sides into real trees
    
        
    You cannot diff text — you diff data. JSON.parse turns each document into a tree of objects, arrays and primitives. Wrap it so an invalid document reports the parse error with a line and column instead of throwing.
    
        
    function parseJSON(text){
  try { return { ok:true, value: JSON.parse(text) }; }
  catch (e){
    const m = /position (\d+)/.exec(e.message);   // V8 puts the byte offset here
    let where = "";
    if (m){
      const pos = +m[1], upto = text.slice(0, pos);
      const line = upto.split("\n").length;
      const col  = pos - upto.lastIndexOf("\n");
      where = " (line " + line + ", column " + col + ")";
    }
    return { ok:false, error: e.message + where };
  }
}
    
      
    2. 
      
  2. 
        
    2
    A type-aware notion of "same"
    
        
    typeof alone is not enough: typeof null and typeof [] both say "object". Write one helper that returns the six JSON shapes so the diff can tell an array from an object from a null — and treat a shape change as a real change.
    
        
    function typeOf(v){
  if (v === null) return "null";
  if (Array.isArray(v)) return "array";
  return typeof v;                 // "object" | "string" | "number" | "boolean"
}
const MISSING = Symbol("missing");  // a key present on one side but not the other
    
      
    3. 
      
  3. 
        
    3
    The recursive core — one node at a time
    
        
    The whole diff is this one function. Missing on one side ⇒ added/removed. Different types ⇒ changed. Same container type ⇒ recurse. Same primitive ⇒ compare. Every case returns a small node describing the verdict.
    
        
    function diffNode(a, b){
  if (a === MISSING) return { kind:"added",   value:b };
  if (b === MISSING) return { kind:"removed", value:a };
  const ta = typeOf(a), tb = typeOf(b);
  if (ta !== tb) return { kind:"changed", cont:false, before:a, after:b };
  if (ta === "object") return diffObject(a, b);
  if (ta === "array")  return diffArray(a, b);
  return a === b ? { kind:"unchanged", cont:false, before:a }
                 : { kind:"changed",   cont:false, before:a, after:b };
}
    
      
    4. 
      
  4. 
        
    4
    Objects: walk the union of keys (order-insensitive)
    
        
    Collect every key from both sides into a set, so reordering keys is invisible and a key on only one side becomes an add or a remove. A container is "changed" if any child changed, else "unchanged".
    
        
    function diffObject(a, b){
  const keys = [...new Set([...Object.keys(a), ...Object.keys(b)])].sort();
  const children = []; let changed = false;
  for (const k of keys){
    const ca = (k in a) ? a[k] : MISSING;
    const cb = (k in b) ? b[k] : MISSING;
    const node = diffNode(ca, cb);              // recurse
    if (node.kind !== "unchanged") changed = true;
    children.push({ key:k, node });
  }
  return { kind: changed ? "changed" : "unchanged", cont:true, ctype:"object", children };
}
    
      
    5. 
      
  5. 
        
    5
    Arrays: align by index
    
        
    Objects have keys to match on; arrays do not, so the simple, predictable rule is to compare position i to position i up to the longer length. Extra tail elements are adds or removes. (This is why an insert near the front cascades — a documented trade-off.)
    
        
    function diffArray(a, b){
  const n = Math.max(a.length, b.length);
  const children = []; let changed = false;
  for (let i = 0; i < n; i++){
    const ca = i < a.length ? a[i] : MISSING;
    const cb = i < b.length ? b[i] : MISSING;
    const node = diffNode(ca, cb);
    if (node.kind !== "unchanged") changed = true;
    children.push({ key:i, node });
  }
  return { kind: changed ? "changed" : "unchanged", cont:true, ctype:"array", children };
}
    
      
    6. 
      
  6. 
        
    6
    Name the location: JSON-Pointer (RFC 6901)
    
        
    A path is just the list of keys/indices you descended through. RFC 6901 joins them with / and escapes the two characters that would otherwise be ambiguous: a literal / in a key becomes ~1, and a literal ~ becomes ~0. The root is the empty string.
    
        
    const escToken = t => String(t).replace(/~/g, "~0").replace(/\//g, "~1");
const pointer  = path => path.length ? path.map(escToken).map(t => "/" + t).join("") : "";
// ["meta","reviews"]      -> "/meta/reviews"
// ["paths","/api/v1"]     -> "/paths/~1api~1v1"
    
      
    7. 
      
  7. 
        
    7
    Turn the tree into an RFC 6902 JSON-Patch
    
        
    Walk the diff nodes carrying the path. An added node is one add, a removed node one remove, a changed leaf one replace (with the whole after-value). A changed container emits nothing itself — you recurse so the ops land on the exact leaves that moved.
    
        
    function buildPatch(node, path, ops){
  switch (node.kind){
    case "added":   ops.push({ op:"add",     path:pointer(path), value:node.value }); break;
    case "removed": ops.push({ op:"remove",  path:pointer(path) }); break;
    case "changed":
      if (node.cont) node.children.forEach(c => buildPatch(c.node, [...path, c.key], ops));
      else ops.push({ op:"replace", path:pointer(path), value:node.after });
      break;
    // "unchanged": emit nothing
  }
}
    
      
    8. 
      
  8. 
        
    8
    Render the tree, colour by verdict
    
        
    Flatten the node tree into indented lines, each tagged with a gutter symbol and a colour: + green for add, − red for remove, ~ amber for a changed leaf (shown as old → new), and a plain line for unchanged. A changed container just brackets its changed children.
    
        
    function emit(key, node, depth, lines){
  if (node.kind === "changed" && !node.cont)
    lines.push(line(depth, "~", "chg",
      label(key) + scalar(node.before) + " → " + scalar(node.after)));
  else if (node.kind === "added")   whole(key, node.value, depth, "add", "+", lines);
  else if (node.kind === "removed") whole(key, node.value, depth, "rem", "−", lines);
  else if (node.cont) { /* bracket + recurse over node.children */ }
  else lines.push(line(depth, " ", "unc", label(key) + scalar(node.before)));
}
    
      
    9. 
      
  9. 
        
    9
    Collapse the noise, count the signal
    
        
    Real diffs are mostly unchanged. A "collapse unchanged" toggle folds those nodes into a dim one-liner so the eye lands on what moved, and a tally over the tree gives the summary — added / removed / changed leaves and unchanged leaves.
    
        
    function tally(node, acc){
  if (node.kind === "added")   { acc.added++;   return; }
  if (node.kind === "removed") { acc.removed++; return; }
  if (node.cont) { node.children.forEach(c => tally(c.node, acc)); return; }
  if (node.kind === "changed")   acc.changed++;     // a changed leaf
  else                           acc.unchanged++;   // an unchanged leaf
}

  10. 
        
    10
    Prove it with a self-test
    
        
    A diff you cannot trust is worse than none. Assert the four verdicts on tiny inputs: an added key, a removed key, a changed value, and — the one that separates structural from textual — two objects with the same keys in a different order coming back unchanged.
    
        
    console.assert(diffNode({a:1}, {a:1, b:2}).children.find(c => c.key==="b").node.kind === "added");
console.assert(diffNode({a:1, b:2}, {a:1}).children.find(c => c.key==="b").node.kind === "removed");
console.assert(diffNode({a:1}, {a:2}).children[0].node.kind === "changed");
console.assert(diffNode({a:1, b:2}, {b:2, a:1}).kind === "unchanged");   // key order ignored ✓
console.assert(diffNode(10, "10").kind === "changed");                    // type matters ✓
